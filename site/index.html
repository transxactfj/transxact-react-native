REACT NATIVE SDK

Payments made easy.
In your React Native app.

Take M‑PAiSA and MyCash payments in FJD with Transxact hosted Checkout Sessions. Your app never holds a secret key and never sets an amount. Pure JavaScript, so it runs in Expo Go.

Get started View on GitHub
npm install @transxact/react-native
01 — How it works

Two legs. Your server in the middle.

The package covers the two parts of a payment that happen in the app. Everything that needs a secret key stays on your Merchant backend. Requires React 18+ and React Native 0.72+ (Expo SDK 49+); nothing to link.

PAY

Create and open

Ask your backend to create a Checkout Session, then open its hosted page in the device browser or an in-app browser tab.

RETURN

Ask, don’t assume

When the Customer comes back through an app link, your backend is asked what really happened. The link is only a hint, never proof of payment.

FULFIL

Trust the webhook

Fulfil orders from signed webhooks on your server. The Return screen only shows the Customer the outcome.

1 · AppCustomer taps Pay
2 · Your backendCreates the session with your key
3 · TransxactHosted page takes the payment
4 · AppApp link reopens it; backend confirms the status
02 — Quickstart

Four pieces of code.

Point the SDK at your backend, add a button, show the result, and give your backend one route. URLs in an app must be absolute: there is no “current page”.

1 · Configure

Wrap your app once so the button and the Return screen share the setup. Use URLs for a simple backend, or your own functions when it needs a different request shape or a bearer token.

The provider is optional: you can pass the same options to each hook or button instead.

import { TransxactProvider } from "@transxact/react-native";

const BACKEND = "https://shop.example/api/checkout";

export default function App() {
    return (
        <TransxactProvider
            createSessionUrl={BACKEND}
            retrieveSessionUrl={BACKEND}
            fetchInit={{ headers: { Authorization: `Bearer ${token}` } }}
        >
            {/* your navigation */}
        </TransxactProvider>
    );
}

2 · Pay button

Say what is bought. The amount is decided by your backend, where the Customer can’t edit it.

The button is disabled and reports busy to screen readers while it works. A string child is wrapped in <Text> for you; style it with textStyle.

import { CheckoutButton } from "@transxact/react-native";
import * as WebBrowser from "expo-web-browser";

export function Cart({ orderId }: { orderId: string }) {
    return (
        <CheckoutButton
            payload={{ orderId }} // never an amount
            redirect={(url) => WebBrowser.openBrowserAsync(url)} // optional in-app browser
            style={{ padding: 12 }}
        >
            Pay with M-PAiSA or MyCash
        </CheckoutButton>
    );
}

3 · Return screen

Polls your backend while the session is pending, then settles on succeeded, failed or cancelled.

state is what the hook is doing; session.status is the payment. Pass the session_id from your router when you can.

import { useCheckoutReturn } from "@transxact/react-native";
import { Button, Text } from "react-native";

export function CheckoutReturn() {
    const { state, session, refresh } = useCheckoutReturn();

    if (state === "missing") return <Text>No payment to show.</Text>;
    if (state === "error") return <Button title="Try again" onPress={refresh} />;
    if (state === "timed_out") return <Text>Still confirming your payment.</Text>;
    if (state !== "settled") return <Text>Confirming your payment…</Text>;
    return <Text>{session?.status}</Text>;
}

4 · Merchant backend

The one piece that runs on your server, not in the app. It uses @transxact/node and your secret key.

It looks up the price, forwards the Idempotency-Key, and reports the status. successUrl and cancelUrl must be https:// app links, not myapp://.

// app/api/checkout/route.ts — server-only
import { TransxactApiClient } from "@transxact/node";

const transxact = new TransxactApiClient({ token: process.env.TRANSXACT_SECRET_KEY! });

export async function POST(request: Request) {
    const { orderId } = await request.json();
    const order = await findOrder(orderId); // your own lookup
    const session = await transxact.checkoutSessions.create({
        idempotencyKey: request.headers.get("Idempotency-Key") ?? crypto.randomUUID(),
        amount: order.totalCents,
        currency: "FJD",
        successUrl: "https://shop.example/checkout/return", // an app link
        cancelUrl: "https://shop.example/checkout/return",
    });
    return Response.json({ id: session.id, hostedUrl: session.hostedUrl });
}

export async function GET(request: Request) {
    const id = new URL(request.url).searchParams.get("session_id")!;
    const session = await transxact.checkoutSessions.retrieve({ id });
    return Response.json({ id, status: session.status });
}
03 — App links

Bring the Customer back to the app.

Transxact returns the Customer to your successUrl or cancelUrl, and both must be https://. Register that URL as a universal link (iOS) and an app link (Android) so it opens your app instead of a web page.

1 · Declare the domain

In Expo this is ios.associatedDomains and android.intentFilters with autoVerify. Bare React Native uses the same entitlement and manifest entries.

{
  "expo": {
    "ios": { "associatedDomains": ["applinks:shop.example"] },
    "android": {
      "intentFilters": [{
        "action": "VIEW",
        "autoVerify": true,
        "data": [{ "scheme": "https", "host": "shop.example", "pathPrefix": "/checkout/return" }],
        "category": ["BROWSABLE", "DEFAULT"]
      }]
    }
  }
}

2 · Host the association files

Your domain must serve /.well-known/apple-app-site-association and /.well-known/assetlinks.json, with no redirects, so the OS can verify that your app owns the link.

curl -i https://shop.example/.well-known/apple-app-site-association
curl -i https://shop.example/.well-known/assetlinks.json

3 · Route it to the Return screen

With Expo Router or React Navigation, map the link to your Return screen and pass session_id in. With no argument, the hook reads it from the launch link, or the next link received while the app is open.

import { useLocalSearchParams } from "expo-router";

export default function Return() {
    const { session_id } = useLocalSearchParams<{ session_id?: string }>();
    const { state, session } = useCheckoutReturn({ sessionId: session_id ?? null });
    // …
}
04 — Safety rules

Built so the unsafe thing can’t happen.

These rules are part of the SDK’s design and are covered by its tests.

No secret keys

The SDK has no key option and never calls Transxact. Every request goes to your Merchant backend. Never put a Transxact key in the app binary.

No amounts

The app says what is bought. Prices are decided on your Merchant backend.

Checked links only

The hosted URL must be https (or http on localhost for local development) before the Customer is sent there.

One key per attempt

A retry after a lost response replays the same Checkout Session, so no double charges.

No double taps

The button is disabled while it creates a session and opens the browser. Repeat presses are ignored.

Request errors aren’t payment failures

A failed lookup is state: "error"; a failed payment is status: "failed". They can’t be confused.

05 — API

Three exports and one error type.

Props on a hook or component always beat the provider. At the same level, a function beats a URL.

<TransxactProvider>

Optional defaults for everything beneath it.

PropWhat it does
createSession / createSessionUrlYour function, or an absolute URL, for creating a Checkout Session
retrieveSession / retrieveSessionUrlYour function, or an absolute URL, for looking one up
fetchInitExtra options for the URL shorthands, e.g. an Authorization header
pollingReturn screen polling defaults: intervalMs, maxIntervalMs, timeoutMs

useCheckout() · <CheckoutButton>

Starts a Checkout attempt and opens the hosted page. The button takes the same options plus any <Pressable> props, and is unstyled.

Option
payloadWhat is being bought — never the price
onErrorCalled when state becomes error
redirectReplace the default Linking.openURL, e.g. with an in-app browser
idle→creating→redirectingorerror

useCheckoutReturn()

Reads session_id, asks your backend, and polls with backoff (1.5 s, 3 s, 6 s, then every 8 s) for up to 60 s.

Option
sessionIdFrom your router; null means none
pollingOverrides the provider field by field
refresh()Starts over after error or timed_out
loading→polling→settledortimed_outerrormissing

TransxactReactNativeError

Errors raised by the SDK carry a code. Errors thrown by your own functions pass through unchanged.

codeWhen
config_missingNeither props nor provider say how to reach your backend
http_errorA URL shorthand got a non-2xx response; error.status and error.body are set
invalid_responseThe response isn’t JSON, or has no valid hostedUrl or status

The full reference, including platform notes (no crypto or URL polyfills needed), is in the README.

06 — Develop and test

From Expo Go to a real device.

Test in three stages, each proving something the last can’t. Use an sk_test_ key on your Merchant backend: Test mode runs simulated payments and moves no money.

1 · Mock the backend

Prove the app side first. Pass your own functions that return canned data and no server is needed. This runs in Expo Go.

The first two polls return pending, so you can watch the Return screen wait and settle. Change outcome to "failed" or "cancelled" to see every ending; the example app has buttons for it.

let polls = 0;
const outcome: "succeeded" | "failed" | "cancelled" = "succeeded";

<TransxactProvider
    createSession={async () => ({ id: "cs_test_123", hostedUrl: "https://example.com" })}
    retrieveSession={async (id) => ({ id, status: ++polls < 3 ? "pending" : outcome })}
>
    …
</TransxactProvider>

2 · Use a real backend

A phone can’t reach localhost on your computer. Expose your dev server over an https tunnel (for example ngrok or Cloudflare Tunnel) and use that URL as BACKEND. The example app ships a ready backend in example/backend: run it with your sk_test_ key, then start the app with EXPO_PUBLIC_BACKEND_URL set to the tunnel URL.

Press Pay, paste the session id into the app, drive the session to each outcome with a test transition, and check it again.

curl -X POST https://api.transxact.io/v1/checkout-sessions/cs_…/test-transition \
  -H "Authorization: Bearer $TRANSXACT_SECRET_KEY" \
  -H "Content-Type: application/json" \
  -d '{"status":"succeeded","provider":"mpaisa"}'

3 · Test the app link

App links don’t work in Expo Go. Make a development build (npx expo run:android, npx expo run:ios or EAS), then fire the link at the device and watch the Return screen open.

On a physical device, tap the link from Notes or Messages to test verification end to end.

# Android device or emulator
adb shell am start -a android.intent.action.VIEW \
  -d "https://shop.example/checkout/return?session_id=cs_test_123"

# iOS simulator
xcrun simctl openurl booted "https://shop.example/checkout/return?session_id=cs_test_123"
